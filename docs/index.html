MailRambo · Source and tests

Email-quality tools for Vercel AI SDK agents

MailRambo AI SDK 0.1.0 adds server-side signup screening and credit inspection. Tested with ai 7.0.126, Zod 4.5.4, mailrambo 0.2.1 and Node 22.23.3/26.7.0. No Vercel endorsement or registry acceptance is implied.

Free by default: screening and account inspection consume no MailRambo verification credits. There is no separate package fee or required hosted wrapper. Model inference, app hosting and optional full mailbox checks can cost money separately. All package tests use mock models and requests.

Install and set up

Check your installed AI SDK version before changing an existing app. The peer requires 7.0.126; do not blindly upgrade or force a conflict. Install the published package in a compatible project:

npm install mailrambo-ai-sdk@0.1.0 ai@7.0.126 zod@4.5.4

Create a dedicated MailRambo API key. Store it as MAILRAMBO_API_KEY on your server, never in a browser-exposed variable or model input.

Use native tools in your agent

import { generateText, isStepCount } from 'ai';
import { mailramboTools } from 'mailrambo-ai-sdk';

const { text } = await generateText({
  model: 'openai/gpt-5-mini', // Provider/gateway access; inference may be billed.
  prompt: 'Screen jane@example.com for signup problems; explain whether the mailbox was checked.',
  tools: mailramboTools(), // Reads server-side MAILRAMBO_API_KEY.
  stopWhen: isStepCount(2),
});
console.log(text);

Do not run the live model example on a $0 testing budget. The repository's real AI SDK loop tests use MockLanguageModelV4, not paid inference. You can also call a tool directly from trusted code without any model:

const tools = mailramboTools();
const result = await tools.screenSignupEmail.execute(
  { email: 'jane@example.com' },
  { toolCallId: 'server-screen-1', messages: [] },
);

This calls the free MailRambo API; API authentication/rate limits and your hosting/network policies apply. Inject fetch fixtures for completely offline tests.

Understand the results

Tool/resultMeaning
screenSignupEmailSyntax, typo, disposable and mail-domain checks. false for known failures, null for no problem found. mailboxChecked is always false.
checkCreditsFree plan/credit inspection; does not buy credits or authorize spending.
ok:falseSanitized API/network/timeout/invalid-response error. No successful deliverability claim.

Fast screening never confirms mailbox existence, ownership or identity. Both live and test keys run real fast checks; full test-key checks are simulated. The tools do not send mail or create accounts. Your app chooses signup behavior when screening is unavailable; do not confuse an unavailable result with a pass. Keep email confirmation, CAPTCHA and rate limits. For a fixed Better Auth signup hook, see the separate Better Auth guide.

Optional paid verification is developer-controlled

Omit this configuration for $0 verification-credit usage. It cannot be enabled by model inputs:

const tools = mailramboTools({
  paidVerification: { maxChecks: 2, timeoutMs: 10000 },
}); // Adds verifyMailbox with needsApproval:true.
  • Full verification can consume one credit; results are strict, with catch-all and uncertain mailboxes not confirmed.
  • AI SDK asks for approval before paid execution. Direct execute calls bypass that loop: the caller must enforce approval.
  • The cap is per toolset instance in memory, not a durable/global account budget. Recreating instances or running other workers resets or duplicates it. Hosts must enforce shared policy where needed.
  • Requests reserve a slot before awaiting RPC; parallel calls cannot exceed the instance cap. Errors/timeouts retain the reservation conservatively. No automatic retries.
  • Model and hosting bills are not controlled by maxChecks. No dollar-budget or identity/consent guarantee is made.

Options and privacy

apiKey defaults to the server environment. fastTimeoutMs defaults to 2000; optional full timeout defaults to 10000ms. fetch must honor AbortSignal. Missing/invalid configuration throws at startup; remote errors are returned as ok:false. Timeouts do not guarantee total agent latency.

Email addresses are transmitted to MailRambo over HTTPS and may appear in your model/app logs. Review data-sharing and logging policies. This package never logs keys/addresses or exposes raw upstream error bodies. It does not perform contact discovery, send emails, change billing or automatically create accounts.
